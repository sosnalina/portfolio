- **Track position moved from static CSS to a per-frame script computation, and the phase offset's own composition had to change along with it.** Phase 1's `transform: scale(...) translateX(<offset>)` on `.qod2-track-scaler` is gone from CSS entirely; `renderScene1`/`trackOffsetNative` (script) set the same `scale()`/`translateX()` shape inline, every frame, from `offset0 + direction × speed × (t/1000)`. `ROW_CARD_NATIVE_WIDTH`/`TRACK_CARD_GAP`/`TRACK_UNIT`/`ROW_CARD_SCALE` (script) mirror the CSS `:root` block's own row-card numbers as plain JS literals (`--qod2-row-card-scale`/`--qod2-track-phase-unit` were removed from CSS as dead once the static rules consuming them were gone — same "CSS calc() can't be read back into JS" limitation `--ag-shadow-bleed`'s own comment documents elsewhere in this file).
- **Direction (spec §7: track 1 right, 2 left, 3 right, 4 left) now actually drives motion, and required working out how a track's own DOM card order maps to on-screen arrival order.** A track's on-screen position is `domIndex × TRACK_UNIT + offset(t)`, and `offset(t)` only ever increases (rightward) or only ever decreases (leftward) — never wraps. For LEFTWARD tracks, DOM order already is arrival order (low DOM index arrives first). For RIGHTWARD tracks it's the reverse — the HIGHEST DOM index arrives first, the lowest last — so `buildTrackQueueHTML` reverses the queue array before inserting it into a rightward track's DOM, and `trackOffsetNative`'s own `startK` (which end of the queue sits at the window at t=0) flips accordingly (`TRACK_QUEUE_LENGTH - 1` for rightward, `0` for leftward). Confirmed by direct observation while tuning the first pass: without the reversal, rightward tracks turned orange starting from their FIRST visible card instead of their last — this was a positioning bug, not a content-timing one, and stayed relevant after fix round 1 replaced the content side entirely (position and content-state are now fully independent — see the cascade's own entry below).

Untouched by fix round 1 (item 3 only changed the DELAY before this fires, not the curves themselves — see that fix's own entry below).

- **Flip (spec §9.4).** `.qod2-footer-flip`/`.qod2-footer-flip-inner`/`.qod2-footer-face`/`.qod2-footer-face--back` markup/CSS are untouched from the kept prior build (spec §11: "do not author a replacement"); `computeFlipAngle`/`renderScene1` set `rotateX` on the flip-inner every frame from `t`, easing through `footerFlipStart`/`footerFlipEnd`. **Fix round 1 (against the phase-2 build above).** Hadar's own follow-up brief, seven items; item 5 (the colour turn) was the significant one. - **2. Queue length raised 8 → 16** (`TRACK_QUEUE_LENGTH`), each track cycling the 8 authored rows twice.
